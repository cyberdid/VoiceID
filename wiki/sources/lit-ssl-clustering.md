# Літературна довідка: self-supervised мовець і кластеризація в масштабі

## ⭐ Головне число: наскільки добре працює навчання без міток

У літературі з ітеративних псевдоміток на VoxCeleb2-dev **без використання міток узагалі**:

| Етап | EER на Vox1-O |
| :-- | --: |
| після 2-ї ітерації кластеризації | **~1,01%** |
| + large margin fine-tuning | **~0,99%** |

Для порівняння з [[models/comparison]] (там мітки використовувались):
supervised ResNet34 (Wespeaker) — 0,723%, оригінальна ECAPA — 0,870%, TDNN — 1,590%.

**Тобто повністю self-supervised система обходить supervised TDNN і майже наздоганяє
supervised ECAPA.** Розрив до найкращої supervised ResNet34 — близько 40% відносно.

Це прямо відповідає на питання «чи вартий заходу цикл з псевдомітками» для
[[concepts/pseudo-label-training]]: **вартий**. *(атрибуцію конкретної цифри до
конкретної статті треба уточнити — у видачі вона згадана без чіткого прив'язування.)*

## ⭐ Канонічний рецепт (DINO → псевдомітки → AAM)

Стандартний двостадійний пайплайн, який варто копіювати як є:

```
Стадія 1: DINO (self-distillation, БЕЗ негативних пар, без міток)
             ↓  початкові ембединги
Стадія 2: k-means з 50 000 центроїдів
             ↓
          AHC до 7 500 кластерів          (VoxCeleb2-dev, де насправді 5 994 диктори)
             ↓  індекси кластерів = псевдомітки
          ResNet34 x-vector + AAM-loss, навчання supervised-стилю
             ↓
          переембединг → перекластеризація → ⟳ 3 рази до збіжності
```

Навчальні семпли — сегменти по **2 секунди** на висловлювання. Дані фіксовані:
VoxCeleb2-dev без міток на весь пайплайн.

**Дві деталі, які варто відзначити окремо:**

1. **Двостадійна кластеризація `k-means → AHC`** — саме так галузь вирішує проблему
   масштабу: k-means дешево ріже мільйони точок на 50 тис. грубих груп, далі AHC
   працює вже на центроїдах, де O(n²) допустиме. Це альтернатива схемі
   «ANN-граф + Leiden» з [[concepts/speaker-clustering]] — і, схоже, більш обкатана
   саме для мовців.

2. **7 500 кластерів при 5 994 реальних дикторах — навмисне перекластеризування на ~25%.**
   Це емпіричне підтвердження правила **«краще перерозділити, ніж перезлити»**, яке
   виведене в [[concepts/speaker-clustering]] з міркувань про несиметричність помилок.
   Галузь робить так само.

## Робота з шумом у псевдомітках

Це визнана центральна проблема — «якість псевдоміток визначає якість системи».
Знайдені методи:

| Метод | Ідея | Посилання |
| :-- | :-- | :-- |
| **DLG-LC** (dynamic loss-gate + label correction) | динамічний поріг у лоссі + виправлення міток на льоту | [arXiv:2208.01928](https://arxiv.org/pdf/2208.01928) |
| **Cluster-Aware DINO (CA-DINO)** | вбудовує інформацію про кластери в саме DINO-навчання | [arXiv:2304.05754](https://arxiv.org/abs/2304.05754) |
| Batch-scale pseudo-label correction | виправлення міток у межах батча | ResearchGate |
| Similarity-connected graphs + GCN | графова нейромережа для уточнення зв'язків | [arXiv:2509.04147](https://arxiv.org/pdf/2509.04147) |
| Використання великих ASR-моделей як фронтенду | «towards supervised performance» | [arXiv:2406.02285](https://arxiv.org/html/2406.02285v1), Interspeech 2024 |

CA-DINO заявляє **22,17% / 27,94% / 25,56%** відносного покращення EER на Vox-O/E/H
проти найкращих на той момент SSL-систем.

## Кластеризація в потрібному нам масштабі

| Метод | Що відомо |
| :-- | :-- |
| **Exact memory-constrained UPGMA** (average linkage) | точна й паралельна реалізація для великих наборів + автовибір кількості кластерів. **Перевірено на 4 млн висловлювань** — це наш порядок ([[datasets/telegram-corpus]]) |
| **HDBSCAN** | добре масштабується, **k знати не треба**, має клас «шум»; з ANN-пошуком значно швидший за повний попарний розрахунок |
| AHC (average-linkage, cosine) | класика; кількість кластерів — зі стрибків дендрограми або максимізацією метрики діаризації |
| k-means → AHC | див. рецепт DINO вище |

Тобто для 4 млн точок є **щонайменше три робочі варіанти**, і принаймні один
перевірений рівно на такому обсязі.

## Моделі, яких не було в нашому каталозі

Обидві знахідки суттєві — див. [[datasets/voxblink2]] і [[models/3d-speaker]].

**VoxBlink2** ([arXiv:2407.11510](https://arxiv.org/abs/2407.11510), Interspeech 2024):
корпус на **110 тис.+ дикторів, ~10 млн висловлювань**, і на ньому — SOTA одиночної
моделі **EER 0,170%** на Vox1-O. Це в 4 рази краще за найкращу модель у нашій таблиці.
Плюс автори вводять власний **Open-Set Speaker-Identification benchmark** —
доповнює [[sources/voxwatch-osi-benchmark]].

**3D-Speaker** ([arXiv:2403.19971](https://arxiv.org/html/2403.19971v3), ModelScope):
тулкіт з **CAM++**, **ERes2Net**, **ERes2NetV2**. ERes2NetV2 — найточніший,
CAM++ — конкурентний за значно меншої обчислювальної вартості.
Претреновані ERes2NetV2 на наборах з **200 тис. дикторів**.

## Дані для валідації: російська

**Golos** ([arXiv:2106.10161](https://arxiv.org/pdf/2106.10161), Interspeech 2021,
SberDevices): ~**1240 годин** російської, краудсорсинг + студійні far-field записи,
у відкритому доступі, є на HuggingFace.

⚠️ **Чи є в Golos мітки дикторів — з видачі незрозуміло.** Корпус ASR-орієнтований.
Треба перевірити структуру: без міток дикторів або хоча б `client_id` він для нас
марний як eval-набір. Питання в [[open-questions]].

## Що це змінює в проєкті

1. **Цикл з псевдомітками — не гіпотеза, а стандартний рецепт** з відомим результатом
   (~1% EER без міток). Підвищує впевненість у [[concepts/pseudo-label-training]].
2. **Є канонічна схема кластеризації** (k-means 50k → AHC), перевірена саме на мовцях.
3. **Перекластеризування на ~25% — норма галузі**, не обережність.
4. **Шортліст моделей треба переглянути**: VoxBlink2- і 3D-Speaker-чекпойнти навчені
   на 100–200 тис. дикторів проти 6 тис. у VoxCeleb. Для корпусу з невідомою
   кількістю мовців і не-англійською мовою це може важити більше за архітектуру.
5. **DINO як стадія 1** — варіант, якого не було в плані: дає стартовий енкодер
   без жодного претренованого чекпойнта.
