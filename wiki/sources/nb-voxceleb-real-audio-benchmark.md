# Джерело: ноутбук «benchmarking using VoxCeleb for real audio»

Kaggle-ноутбук (11 клітинок, виконаний, з outputs). Kaggle-метадані: 5 датасетів +
2 kernel-версії, GPU вимкнено в метаданих, але лог показує `Running on: cuda`.

> ⚠️ **Задача НЕ та, що в решті проєкту.** Це **anti-spoofing / детекція діпфейків**
> (справжній голос vs синтезований ElevenLabs), а не ідентифікація мовця.
> VoxCeleb тут використано лише як джерело «справжніх людських голосів».
> Модель — бінарний класифікатор, а не енкодер ембедингів; вона не вміє відповісти
> «хто це говорить». Див. [[concepts/anti-spoofing]] і питання про скоуп в [[open-questions]].
>
> Цінність для нас — **не результати, а інженерні патерни**: telephony-фільтр,
> схема поступового розморожування шарів, discriminative LR, обчислення EER, поводження
> з порогами. Плюс — повчальний приклад того, як не треба міряти.

## Архітектура

```python
class WaveFakeModel(nn.Module):
    ssl_frontend = Wav2Vec2Model.from_pretrained("facebook/wav2vec2-base")   # 768-dim
    classifier   = Linear(768,512) → ReLU → Dropout(0.3) → Linear(512,1)     # 1 логіт
    forward: classifier(ssl(x).last_hidden_state.mean(dim=1))                # mean-pooling
```

Мітки: **1.0 = справжня людина (bonafide)**, **0.0 = ElevenLabs (spoof)**.
Тобто «висока ймовірність = людина», і поріг спрацьовує як `prob < θ → діпфейк`.

## Препроцесинг — «telephony filter»

```python
telephony_filter = nn.Sequential(T.Resample(16000, 8000), T.Resample(8000, 16000))
```
Симуляція телефонного каналу: даунсемпл до 8 кГц і назад до 16 кГц — необоротно вирізає
все вище ~4 кГц. Далі: mono (усереднення каналів), resample до 16 кГц, обрізання/паддінг
до рівно **64000 семплів = 4,0 с**.

**Це напряму застосовне до нашої задачі**, якщо цільові дані — телефонні. Див.
[[concepts/audio-preprocessing]] і [[concepts/domain-mismatch]].

## Дані та тренування

Джерела: ElevenLabs dataset (900 треків, mp3/wav), In-The-Wild real (`release_in_the_wild/real`),
VoxCeleb1 `vox1_dev_wav/wav`.

Train/val: 900 ElevenLabs + 900 human (450 In-The-Wild + 450 VoxCeleb1) →
**1440 train (720/720) / 360 val (180/180)**, `random.seed(42)`.

**Етап 1 (V6 Gold)** — від чекпойнта `telephony_forensics_v1_final.pth`:
заморожено все, крім `layers.11`; Adam lr 2e-5, CosineAnnealingLR T_max=10, batch 16, 10 епох, BCEWithLogits.
Val EER: 29,44 → 16,67 → 13,33 → 12,78 → 12,78 → 12,22 → 10,56 → 11,11 → **10,00** → 10,56.
Підсумок: **EER 10,00%**, accuracy 90,00%, F1 0,9000, поріг **0,2725**.

**Етап 2 (V7 Elite)** — розморожено `layers.8–11` + `feature_projection`;
**discriminative LR**: 3e-6 для ssl_frontend, 2e-5 для classifier; AdamW weight_decay 0,01;
CosineAnnealingLR T_max=12; grad clipping max_norm=1,0; 12 епох.
Val EER: 6,67 → 5,00 → 3,33 → 3,33 → 2,22 → 2,78 → **1,67** → 2,22 ×5.
Підсумок: **EER 1,67%**, accuracy 98,33%, F1 0,9833, поріг **0,2611**.

Розморожування 4 верхніх трансформерних блоків замість одного дало **6-кратне падіння EER**
(10,00% → 1,67%). Ключовий рецепт — [[concepts/fine-tuning]].

## Дефекти, які треба знати (важливо)

1. **Баг форматування відсотків.** У коді `rate = (x/n)*100`, а друкується `{rate:.2%}` —
   подвійне множення. Тому в outputs стоїть `8425.00%`, `9600.00%`, `8285.71%`, `8000.00%`,
   `9283.33%`. **Реальні значення — поділити на 100** (84,25%, 96,00%, …). У cell 8 автор
   порахував інакше і там 85,71% коректно.
2. **Баг друку в cell 2**: `f"{prob_v5:.4f:<10}"` — недійсний format spec, виняток
   ковтається `except: pass`, тому таблиця перших 10 файлів порожня. На підрахунки не впливає
   (лічильники інкрементуються до друку).
3. **Val-сет використано двічі**: для early stopping (вибір найкращої епохи) **і** для
   фінального звіту, і на ньому ж підібрано поріг (`final_optimal_threshold`).
   → EER 1,67% **оптимістичний**, це не held-out оцінка.
4. **`best_eer = 0.1000` на старті етапу 2** — звіт V7 показує «найкращий» EER, а не EER
   фінальної епохи (2,22%).
5. **Тихе ковтання помилок**: `except: return torch.zeros(max_len)` у Dataset підмінює
   нечитабельні файли тишею **зі збереженою міткою** → мовчазне отруєння train-сету.
6. **Головне.** Val EER 1,67% vs 20% пропущених діпфейків на невидимому наборі
   `more-ai-generated-voice` (cell 7). Це не шум — це **перенавчання на домен ElevenLabs**.
   Класична ілюстрація [[concepts/domain-mismatch]]: метрика на in-domain val нічого не
   каже про поведінку на іншому генераторі.
7. Файл `4.mp3` стабільно проходить як «людина» на всіх моделях і порогах
   (V5 0,6012 / Fresh 0,9347 / V7 0,9372) — або це помилково розмічений справжній запис,
   або якісний діпфейк.
8. Поріг **0,85** замість 0,2611 підняв перехоплення 80,00% → 85,71%, але ціною падіння
   пропуску людей 100% → 92,83% (43 хибні тривоги з 600). Наочна демонстрація, чому
   **одне число точності без вказаної робочої точки нічого не варте** —
   [[concepts/eer-and-metrics]].

## Уроки для нашого проєкту

- Схема **поступового розморожування + discriminative LR + grad clipping** — робочий
  шаблон для дотреновування будь-якого SSL-фронтенду, зокрема WavLM у задачі мовця.
- **Telephony filter** — готовий інструмент для симуляції 8 кГц каналу з 16 кГц даних
  (дешева аугментація, якщо цільовий домен телефонний).
- **Ніколи не звітувати метрику на тому ж наборі, на якому обирався поріг і епоха.**
- Обов'язково тримати **третій, зовнішній набір** з іншого домену.
