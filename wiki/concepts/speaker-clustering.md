# Кластеризація мовців (speaker clustering)

Нова основна задача проєкту: у корпусі [[datasets/telegram-corpus]] немає міток —
треба **самим виявити, які записи належать одній людині**.

## Чим це відрізняється від ідентифікації

| | Ідентифікація (OSI) | **Кластеризація** |
| :-- | :-- | :-- |
| Вхід | база відомих + запит | лише купа записів |
| Питання | «хто це зі списку?» | «які записи від однієї людини?» |
| Кількість класів | відома | **невідома** |
| Поріг | можна крутити під кожен запит | **один на весь корпус** |
| Ціна помилки | локальна | **накопичувальна** |

**Найважливіша відмінність — асиметрія помилок.** Одне хибне злиття (merge) назавжди
руйнує два кластери, і далі помилка поширюється транзитивно. Хибне розділення (split)
лишає два чисті кластери, які можна злити пізніше.

> **Правило: краще перерозділити, ніж перезлити.** Починати з високого порога,
> отримати багато дрібних чистих кластерів, і зливати їх на другому проході.
> *(висновок агента)*

Це прямо протилежно налаштуванню порога у верифікації, де EER — розумний компроміс.
Тут потрібна **робоча точка з дуже низьким FAR**, у дусі FRR@FAR=0,5% з
[[concepts/eer-and-metrics]].

## Пайплайн

```
2 ТБ Telegram
 → 0. інвентаризація + дедуплікація (хеш декодованого PCM)
 → 1. декодування ffmpeg → 16 кГц mono
 → 2. VAD (Silero) — прибрати тишу й не-мовлення
 → 3. фільтр якості: тривалість ≥3 с, SNR, частка мовлення
 → 4. вікна 3–5 с з кроком (або 1 ембединг на повідомлення)
 → 5. ембединги (ResNet34-LM / ECAPA)
 → 6. length-norm + AS-Norm по когорті
 → 7. ANN-граф (FAISS HNSW, cosine) → відсікання за порогом
 → 8. кластеризація на графі (Leiden / mutual-kNN + CC)
 → 9. уточнення всередині великих кластерів (AHC)
 → 10. оцінка чистоти
```

## Крок 4: скільки ембедингів на повідомлення

Голосове повідомлення Telegram — зазвичай **один мовець**, тож достатньо одного
ембединга. Але:

**Дешевий детектор багатомовності:** розбити повідомлення на вікна по 3 с, витягти
ембединги, порахувати **розкид косинусної відстані всередині повідомлення**.
Малий розкид → один мовець, усереднити у фінальний ембединг.
Великий → пересилання/розмова/музика → на діаризацію або у смітник.

Бонус: цей самий розкид — **безкоштовна оцінка якості запису**, придатна як ознака
для QMF-калібрації ([[concepts/score-normalization]]).

## Крок 7–8: кластеризація в масштабі

При мільйонах записів AHC і спектральна кластеризація (O(N²)+) неможливі.

| Підхід | Плюси | Мінуси |
| :-- | :-- | :-- |
| k-means (FAISS) | швидко, масштабно | треба знати k; кулясті кластери; погано з викидами |
| **ANN-граф + Leiden/Louvain** | масштабно, k не потрібне, стійке до викидів | треба підібрати поріг і resolution |
| mutual-kNN + connected components | найпростіше | **ланцюжковий ефект**: A~B, B~C, A≁C → все зливається в один кластер |
| HDBSCAN над ANN | сам знаходить k, має клас «шум» | важче тюнити, повільніше |
| NME-SC (спектральна з авто-оцінкою k) | стандарт діаризації | тільки на невеликих підмножинах |
| **k-means (50k) → AHC** | ⭐ **стандарт галузі для мовців**; k-means ріже мільйони точок дешево, AHC доуточнює вже на центроїдах | двоетапність, треба задати обидва параметри |
| **Exact memory-constrained UPGMA** | точна паралельна реалізація + автовибір k; **перевірена на 4 млн висловлювань** — наш порядок | складніша реалізація |
| Онлайн/інкрементальна | дешево, потоково | залежить від порядку, дрейф центроїдів |

**Рекомендація — брати обкатаний галуззю шлях, а не винаходити:**

**Основний варіант (стандарт для мовців, [[sources/lit-ssl-clustering]]):**
`k-means з 50 тис. центроїдів → AHC (average-linkage, cosine) до цільової кількості`.
Саме так працює канонічний DINO-пайплайн, і саме він дав ~1% EER без міток.

**Скільки кластерів цільових.** У референсному рецепті — **7 500 при 5 994 реальних
дикторах**, тобто **перекластеризування на ~25%**. Це емпіричне підтвердження правила
вище: галузь свідомо перестраховується в бік дроблення. У нас реальна кількість
невідома, тож брати оцінку зверху.

**Альтернатива:** FAISS HNSW k-NN граф (k≈50, cosine) → відсікання за порогом →
**mutual-kNN** проти ланцюжків → **Leiden**. Гнучкіше з викидами; та сама математика,
що у великомасштабній кластеризації облич.

**Третій варіант:** **HDBSCAN** над ANN — сам знаходить кількість кластерів і має
клас «шум» (корисно: не-мовлення і сміття не доведеться зливати кудись насильно).

**Про розмір індексу:** 4–44 млн ембедингів × 256 вимірів — це 4–45 ГБ у fp32,
2–22 ГБ у fp16. **Індекс вміщується в RAM навіть у верхньому сценарії.**
Вузьке місце — не кластеризація, а декодування й витяг ембедингів.

## Калібрація без міток

У корпусі **немає жодних метаданих** ([[datasets/telegram-corpus]]) — ані відправника,
ані підказок. Поріг усе одно треба звідкись узяти. Трійка, яка це закриває:

**1. Split-half → розподіл позитивів.** Розрізати кожен запис навпіл і обробити
половини як два незалежні записи. Вони **гарантовано** від одного мовця — без жодної
розмітки. Дає повний розподіл same-speaker скорів.

⚠️ Зміщення: половини одного запису мають той самий канал, ту саму сесію, той самий
шумовий фон → задача штучно легша, розподіл зсунутий вправо. Наслідок — обраний поріг
буде **надто суворим**, тобто помилка піде в бік **перерозділення**. За правилом вище
це **безпечний напрямок**. Пом'якшити можна, беручи не суміжні половини, а рознесені
чверті з проміжком.

**2. Випадкові пари → розподіл негативів.** Якщо мовців у корпусі багато, випадкова
пара записів майже напевно від різних людей; забруднення ≈ 1/N_мовців. Практично
безкоштовний і досить чистий розподіл impostor-скорів.

**1 + 2 разом дають наближену DET-криву взагалі без розмітки.**

**3. ~200 вручну розмічених пар — але правильних.** Єдиний абсолютний якір. Ключове:
розмічати **не випадкові пари** (вони всі тривіально різні й нічого не кажуть), а пари
**в зоні невизначеності навколо кандидатного порога**. 200 прикордонних пар інформативніші
за тисячі випадкових.

**Плюс безрозміточний детектор помилок: згода двох енкодерів.** Якщо ResNet34 і ECAPA
незалежно ставлять пару разом — імовірність висока; розходяться — пара підозріла.
Той самий принцип, що дав −44% FAR у fusion ([[sources/voxwatch-osi-benchmark]]),
застосований без міток.

### Залишкова структура файлів

Навіть без JSON варто перевірити теки й імена: якщо **тека = чат**, то в діалозі 1:1
всі голосові — від двох людей, і це майже повертає слабку розмітку. Timestamp'и в
іменах дають часову структуру розмови. Дублікати/пересилання дають ідеальні позитиви.
Див. [[datasets/telegram-corpus]].

### І далі — не просто калібрувати, а вчити

Отримані кластери — це псевдомітки, на яких можна **навчати власний енкодер під домен**.
Це головний важіль проєкту: [[concepts/pseudo-label-training]].

## Метрики

- **B-cubed precision / recall / F** — стандарт для кластеризації мовців та облич;
  рахує чистоту з погляду кожного елемента, коректно карає і злиття, і дроблення.
- **NMI / ARI** — зручні для порівняння прогонів між собою.
- **Cluster purity** + розподіл розмірів кластерів (гігантський кластер = перезлиття).
- **DER** — лише якщо всередині записів є діаризація.

## Пастки

1. **Ланцюжковий ефект** — головна причина «одного кластера на весь корпус».
2. **Кластеризація каналу, а не голосу** — якщо в корпусі є різні кодеки/пристрої,
   модель згрупує за ними. У Telegram кодек однорідний, тому ризик нижчий.
3. **Короткі записи** — <3 с дають ненадійні ембединги і «сміттєві» кластери.
   Фільтрувати за тривалістю **до** кластеризації.
4. **Не-мовлення** — музика й меми утворюють щільні фальшиві кластери.
5. **Дисбаланс** — кілька дуже активних відправників дадуть величезні кластери,
   решта — синглтони. Розподіл розмірів завжди дивитись у лог-шкалі.
