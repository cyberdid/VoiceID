# Препроцесинг аудіо

Практичний чекліст. Помилки тут коштують більше, ніж вибір моделі.

## Обов'язкові перетворення

| Параметр | Цільове значення | Як привести |
| :-- | :-- | :-- |
| Sampling rate | **16 кГц** — стандарт для всіх моделей проєкту | `torchaudio.transforms.Resample(sr, 16000)` |
| Канали | **1 (mono)** | `torch.mean(wav, dim=0, keepdim=True)` |
| Тривалість | фіксована для батчів | обрізання + `F.pad` |

Типові вхідні sr, на які варто розраховувати:
- **8 кГц** — телефонний канал;
- **44,1 / 48 кГц** — голосові повідомлення з мікрофона телефону;
- 16 кГц — уже готово.

## Робочий код

З [[sources/nb-voxceleb-real-audio-benchmark]] — компактний і повний:

```python
wav, sr = torchaudio.load(path)
if wav.shape[0] > 1:                       # stereo → mono
    wav = torch.mean(wav, dim=0, keepdim=True)
if sr != 16000:                            # → 16 кГц
    wav = T.Resample(sr, 16000)(wav)
if wav.shape[1] > MAX_LEN:                 # фіксована довжина
    wav = wav[:, :MAX_LEN]
else:
    wav = F.pad(wav, (0, MAX_LEN - wav.shape[1]))
```

## Симуляція телефонного каналу

```python
telephony_filter = nn.Sequential(T.Resample(16000, 8000), T.Resample(8000, 16000))
```

Даунсемпл і назад — необоротно вирізає все вище ~4 кГц. Дає з широкосмугового запису
щось акустично схоже на телефонний. Дешева й дуже доречна **аугментація**, якщо цільові
дані телефонні. Наслідки для формант — [[concepts/acoustic-features]].

## Тривалість

- Довші зразки → більше фонетичної інформації → вища точність
  ([[sources/voice-id-parameters-methods]]).
- Різні моделі мають різні мінімуми: одні працюють від **~3 с**, іншим потрібно **~10 с**
  ([[sources/pretrained-models-review]]).
- **Різке спадання віддачі після ~30 с** ([[sources/voxwatch-osi-benchmark]]:
  30 с enroll / 30 с test дає «пристойну» якість, далі приріст маргінальний).
- Практичний дефолт VoxWatch: **enroll 30 с, test 5 с**.
- У ноутбуці — 64000 семплів = рівно **4,0 с**; для anti-spoofing вистачає, для
  ідентифікації мовця це на нижній межі.

## Параметри ознак (стандарт де-факто)

З [[sources/wespeaker-toolkit]] — конфіг, на якому отримані числа рівня 0,45–0,72% EER:

| Параметр | Значення |
| :-- | :-- |
| Ознаки | 80-вимірні log Mel-filterbank (Fbank) |
| Вікно / крок | **25 мс / 10 мс** |
| Довжина чанка при навчанні | **200 кадрів** (= 2 с) |
| Нормалізація | **CMN** (cepstral mean normalization), **без CVN** |
| SpecAug | **вимкнено** — несумісний з іншими аугментаціями |

Пор.: VoxWatch використовує 64-dim log-mel для ResNet-34 і 80-dim для ResNet-124.
80-dim Fbank — найбезпечніший дефолт.

## VAD

Voice activity detection — відкидає ділянки без мовлення. Потрібен, бо тиша й фоновий
шум псують і ембединг, і pooling.

⚠️ Але: **у VoxWatch VAD навмисно не застосовували** (беруть перші t секунд запису) —
щоб бенчмарк був відтворюваним. Якщо порівнюємось із їхніми числами, треба або теж без
VAD, або усвідомлювати різницю.

**Скільки коштує поганий VAD** — [[sources/wespeaker-toolkit]], діаризація на VoxConverse dev:

| SAD | DER |
| :-- | --: |
| oracle (ідеальний) | **4,2%** |
| system (Silero-VAD) | **7,1%** |

Майже **половина** помилок діаризації походить не з розрізнення мовців, а з детекції
мовлення. Якщо в нашому пайплайні буде VAD — його якість треба міряти окремо, інакше
неможливо зрозуміти, що саме зламалось.

⚠️ І: **агресивне шумозаглушення може погіршити точність** — воно спотворює або видаляє
частини мовленнєвого сигналу ([[sources/voice-id-parameters-methods]]).

## Кодеки

- **Lossy** (MP3) — відкидає інформацію, потенційно тонкі голосові характеристики.
- **Lossless** (FLAC) — зберігає все, більший розмір.
- **Speex, Linear16** — оптимізовані під мовлення.
- ⚠️ **Різні кодеки на enroll і test → неузгодженість і падіння точності.** Те саме
  стосується різних sampling rate.

## Правило

**Однаковий препроцесинг на enrollment і на тесті.** Будь-яка асиметрія (кодек, sr,
тривалість, наявність VAD) створює штучну відмінність, яку модель прочитає як «інший мовець».
Це та сама проблема, що [[concepts/domain-mismatch]], тільки створена власноруч.

## Бібліотеки

`torchaudio`, `librosa`, `soundfile` — завантаження й перетворення.
`librosa` — ще й MFCC, мел-спектрограми, оцінка F0.
`SpeechBrain` — pretrained-енкодери + ознаки + протоколи оцінювання.
`pyAudioAnalysis` — базові ознаки, класифікація, сегментація.
