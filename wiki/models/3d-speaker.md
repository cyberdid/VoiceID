# 3D-Speaker (CAM++ / ERes2Net / ERes2NetV2)

[arXiv:2403.19971](https://arxiv.org/html/2403.19971v3) ·
[github](https://github.com/modelscope/3D-Speaker) · чекпойнти на ModelScope

Тулкіт від ModelScope/Alibaba для верифікації, розпізнавання та діаризації мовця.
**Не був у каталозі проєкту** — знайдено веб-дослідженням 2026-08-27.

## ⭐ Короткі записи — профільна перевага ERes2NetV2

[arXiv:2406.02167](https://arxiv.org/html/2406.02167v1), Interspeech 2024:

| Тривалість | ERes2Net | ERes2NetV2 |
| :-- | --: | --: |
| повна | 0,84% | 0,61% |
| **3 с** | 1,89% | **0,98%** (−48,1%) |
| **2 с** | 3,28% | **1,48%** (−54,8%) |

Модель спроєктована саме під короткі висловлювання (BDFF + BLFF). Для
[[datasets/telegram-corpus]], де записи 3–15 с, це вирішальний аргумент —
див. [[concepts/short-duration]].

## Бонус: готовий RDINO

`egs/voxceleb/sv-rdino` — self-supervised DINO для мовця. Готова реалізація стадії 1
з [[concepts/pseudo-label-training]], не треба писати з нуля.

Рецепти є під 3D-Speaker, VoxCeleb і CN-Celeb. Є діаризація.

## Чому це релевантно саме нам

**1. 200 тис. дикторів у тренуванні.** Проти 6 тис. у VoxCeleb. Той самий аргумент,
що й для [[datasets/voxblink2]]: для чужого домену й невідомої кількості мовців
широта тренувальних даних важить більше за архітектуру
([[concepts/domain-mismatch]]).

**2. CAM++ — дешевий.** У задачі, де треба прогнати **мільйони** записів
([[datasets/telegram-corpus]]), обчислювальна вартість на запис — не другорядна
деталь. Якщо CAM++ дає майже ту саму точність за менші гроші, на повному прогоні
це виграш у добах.

**3. Рецепти під CN-Celeb.** Тобто тулкіт відкатаний не лише на англійській —
див. [[datasets/cnceleb]].

**4. Є діаризація** — знадобиться, якщо в записах виявиться більше одного мовця
([[concepts/task-types]]).

## Місце в шортлісті

Кандидат нарівні з [[models/wespeaker]]. Обидва — тулкіти з великими претренованими
чекпойнтами й повними рецептами навчання; обидва підходять і як джерело ембедингів,
і як інструмент для етапу з псевдомітками ([[concepts/pseudo-label-training]]).

Розумно взяти **по одному чекпойнту з кожного** — вони архітектурно різні, отже
придатні і для fusion, і для безрозміточної перевірки згодою
([[concepts/speaker-clustering]]).

## Що лишилось перевірити

- Vox1-E / Vox1-H — у README їх немає.
- Чи є дзеркала на HuggingFace (ModelScope з деяких регіонів може бути незручним).
- Реальна пропускна здатність CAM++ проти ResNet34 на батчах — виміряти в пілоті.
- Чи не постраждає ERes2NetV2 на російській через китайськоцентричне тренування.
