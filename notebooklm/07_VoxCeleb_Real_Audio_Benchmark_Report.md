## 2. Архітектура моделі та препроцесинг

### 2.1. Нейромережева модель WaveFakeModel
```python
import torch
import torch.nn as nn
from transformers import Wav2Vec2Model

class WaveFakeModel(nn.Module):
    def __init__(self):
        super().__init__()
        # Базовий SSL фронтенд від Facebook (768-вимірні репрезентації)
        self.ssl_frontend = Wav2Vec2Model.from_pretrained("facebook/wav2vec2-base")
        # Класифікаційна голова для бінарної детекції
        self.classifier = nn.Sequential(
            nn.Linear(768, 512),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(512, 1)
        )

    def forward(self, x):
        # Отримання прихованих станів останнього трансформерного шару
        outputs = self.ssl_frontend(x).last_hidden_state
        # Усереднення за часовою віссю (Mean Temporal Pooling)
        pooled = outputs.mean(dim=1)
        # Вихідний логіт ймовірності
        return self.classifier(pooled)
```
- **Логіка класифікації:** Вихідний сигнал інтерпретується через Sigmoid.
  - Мітка `1.0` = **Справжня жива людина (Bonafide human)**.
  - Мітка `0.0` = **Синтезований діпфейк (ElevenLabs spoof)**.
  - Правило спрацьовування: якщо $\sigma(\text{logit}) < \theta$, аудіо вважається штучно згенерованим діпфейком.

### 2.2. Акустичний Telephony Filter
Для симуляції проходження сигналу крізь вузькосмуговий телефонний канал зв'язку автор реалізував конвеєр:
```python
import torchaudio.transforms as T

telephony_filter = nn.Sequential(
    T.Resample(16000, 8000),   # Даунсемплінг зрізає частоти вище 4 кГц
    T.Resample(8000, 16000)   # Апсемплінг повертає частотну сітку для бекбону
)
```
- Додатково аудіо приводиться до моно (усереднення стереоканалів) та фіксованої довжини у **64 000 семплів (рівно 4,0 секунди)** шляхом обрізання або циклічного заповнення нулями (padding).

## 3. Двоетапне навчання та результати

### 3.1. Датасети навчання
- **ElevenLabs Dataset:** 900 синтетичних семплів (mp3/wav).
- **Людські голоси:** 450 файлів з In-The-Wild + 450 файлів з VoxCeleb1 dev.
- **Розподіл:** 1 440 train (720 людських / 720 фейків) та 360 validation (180 людських / 180 фейків), `random.seed(42)`.

### 3.2. Фаза 1: Чекпойнт V6 Gold (Початкове розморожування)
- **Конфігурація:** Заморожено весь Wav2Vec2, окрім останнього 12-го трансформерного блоку (`layers.11`). Оптимізатор Adam (lr=2e-5), CosineAnnealingLR (T_max=10), 10 епох.
- **Динаміка валідаційного EER по епохах (%):**
  `29.44 → 16.67 → 13.33 → 12.78 → 12.78 → 12.22 → 10.56 → 11.11 → 10.00 → 10.56`
- **Фінал V6:** EER **10,00%**, Accuracy 90,00%, оптимальний поріг **0,2725**.

### 3.3. Фаза 2: Чекпойнт V7 Elite (Discriminative Fine-Tuning)
- **Конфігурація:** Розморожено 4 верхні блоки (`layers.8`, `9`, `10`, `11`) та шар проекції `feature_projection`.
- **Диференційований темп навчання (Discriminative LR):**
  - Фронтенд Wav2Vec2: $3 \times 10^{-6}$ (дуже обережне донавчання, щоб не зруйнувати базові акустичні репрезентації).
  - Класифікатор: $2 \times 10^{-5}$.
  - Градієнтний кліпінг: `clip_grad_norm_(max_norm=1.0)`.
- **Динаміка валідаційного EER (%):**
  `6.67 → 5.00 → 3.33 → 3.33 → 2.22 → 2.78 → 1.67 → 2.22 → 2.22 → 2.22`
- **Фінал V7:** EER **1,67%**, Accuracy 98,33%, оптимальний поріг **0,2611**.
- **Ефект:** Розморожування 4 блоків замість 1 зменшило помилку EER у **6 разів** (з 10,00% до 1,67%).

## 5. Виявлені дефекти та методологічні пастки

Детальний аналіз коду виявив вісім серйозних вад, критично важливих для уникнення у проєкті VoiceID:

1. **Баг подвійного множення відсотків у форматуванні:**
   У коді написано `rate = (x / n) * 100`, а в рядку друку вказано `{rate:.2%}`. Специфікатор `:.2%` автоматично множить число на 100 і додає знак `%`. Через це у звіті з'явилися абсурдні цифри: `8425.00%`, `9600.00%`, `8000.00%`, `9283.33%`. Реальні значення отримуються простим діленням на 100.
2. **Збій синтаксису форматування у клітинці 2:**
   Рядок `f"{prob_v5:.4f:<10}"` містить некоректну комбінацію специфікаторів у Python, що викликало виняток `ValueError`. Оскільки весь блок було загорнуто в `try ... except: pass`, помилка проковтнулася, і вивід таблиці перших 10 файлів виявився повністю порожнім.
3. **Подвійне використання валідаційного набору (Double Dipping):**
   Один і той самий набір з 360 файлів використовувався для ранньої зупинки (вибору найкращої епохи), для розрахунку оптимального порогу $\theta$ і для фінального звіту точності. Як наслідок, заявлений EER 1,67% є суттєво оптимістичним і не відображає якість на реальних нових даних.
4. **Тихе отруєння датасету нульовими векторами:**
   У класі `Dataset` реалізовано:
   ```python
   except Exception:
       return torch.zeros(max_len), label
   ```
   Якщо аудіофайл був пошкоджений, замість помилки модель навчалася на масиві тиші з міткою людини або фейка, забруднюючи простір градієнтів.
5. **Катастрофічний розрив доменів (Domain Mismatch):**
   Модель, що мала EER 1,67% на валідації, пропустила **20% діпфейків** на невідомому наборі `more-ai-generated-voice` (клітинка 7). Модель вивчила специфічні спектральні шуми вокодера ElevenLabs, а не загальний принцип відмінності синтетичного мовлення від людського.
6. **Аномалія файлу `4.mp3`:**
   Файл стабільно визначається як «людина» з імовірністю >93% усіма моделями. Це вказує або на помилкову розмітку датасету, або на дуже високу якість синтезу, яку не ловлять частотні моделі.
7. **Ціна зміни порогу:**
   Збільшення порогу з 0,2611 до 0,85 допомогло підняти виявлення діпфейків з 80% до 85,71%, проте викликало 43 хибні тривоги на людях (успішний пропуск людей впав зі 100% до 92,83%).

## 6. Інженерні уроки для VoiceID

- **Шаблон Discriminative Fine-Tuning:** Схема повільного навчання трансформерних шарів ($3 \times 10^{-6}$) та швидшого навчання вихідної голови ($2 \times 10^{-5}$) з кліпінгом градієнтів $1.0$ є бездоганним рецептом для донавчання великих моделей (WavLM, SimAM).
- **Використання Telephony Filter:** Код симуляції 8 кГц телефонного каналу готовий до застосування у пайплайні VoiceID як аугментація даних для підвищення стійкості до перехоплень низької якості.
- **Непохитна вимога Hold-Out тесту:** Заборонено звітувати точність на наборі підбору порогу.
