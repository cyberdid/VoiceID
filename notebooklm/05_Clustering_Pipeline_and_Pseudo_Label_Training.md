# Пайплайн масштабної кластеризації та навчання на псевдомітках (Clustering & Pseudo-Label Training)

## 1. Архітектура масштабного пайплайну неконтрольованої кластеризації

Обробка масиву у ~2 ТБ нерозміченого аудіо вимагає спеціальної архітектури, розрахованої на запобігання перевантаженню дискової підсистеми (I/O Bottleneck) та коректну роботу графових алгоритмів.

```
Цільовий масив Telegram (~2 ТБ .ogg)
               │
               ▼
   [1. Tar-шардування (UIO)] ──► Пакування в архіви по 1–2 ГБ (вирішення проблеми I/O)
               │
               ▼
   [2. Паралельний CPU декод] ──► Перетворення у 16 кГц PCM Mono
               │
               ▼
   [3. Silero VAD фільтрація] ──► Видалення тиші, фільтр тривалості (чисте мовлення ≥ 3,0 с)
               │
               ▼
   [4. Подвійний енкодер] ────► SimAM-ResNet34 (512-dim) + ERes2NetV2 (192-dim)
               │
               ▼
   [5. FAISS HNSW граф] ──────► Cosine індекс, k=50 найближчих сусідів
               │
               ▼
   [6. Фільтр взаємності] ────► Відсікання ребер < θ_calib, взаємні сусіди (Mutual kNN)
               │
               ▼
   [7. Leiden + Внутрішній AHC] ──► Виділення спільнот мовців (кластерів)
```

### 1.1. Етап 1: Tar-шардування у стилі UIO (Unified I/O / WebDataset)
- **Проблема:** Зберігання 2–4 мільйонів окремих файлів `.ogg` на файловій системі ext4/ZFS призводить до вичерпання інодів (inodes), блокування файлових дескрипторів та падіння швидкості читання до десятків кілобайт на секунду.
- **Рішення:** Попереднє об'єднання файлів у послідовні tar-архіви розміром 1–2 ГБ. Читання відбувається потоково великими блоками без випадкового доступу до диску.

### 1.2. Етап 2–3: Препроцесинг та Silero VAD
- Паралельне декодування процесорними потоками (CPU) за допомогою `ffmpeg`.
- Пропуск через Silero VAD: сегменти розбиваються на чанки чистого мовлення. Фрагменти із загальною тривалістю мовлення менше 3,0 с відкидаються, оскільки вони мають високу ймовірність деградації ембедингу.

### 1.3. Етап 4: Екстракція ембедингів двома архітектурами
Використовуються одночасно два взаємодоповнюючі енкодери:
1. **SimAM-ResNet34** (512 вимірів, база VoxBlink2),
2. **ERes2NetV2** (192 виміри, база ModelScope).
- Для кожного повідомлення витягуються ембединги ковзними вікнами (по 3–5 с), після чого рахується **середній ембединг повідомлення** та **внутрішньоповідомна дисперсія** (variance). Висока дисперсія слугує індикатором того, що у файлі присутні двоє мовців або немовний шум.

## 2. Графова кластеризація та відсікання помилок злиття

### 2.1. Побудова графа подібності через FAISS HNSW
- Для мільйонів ембедингів точний пошук усіх попарних відстаней ($O(N^2)$) неможливий.
- Використовується наближений індекс **Hierarchical Navigable Small World (HNSW)** з метрикою внутрішнього добутку (Inner Product на $L_2$-нормалізованих векторах = косинус).
- Параметри: $M = 32$, $efSearch = 64$, $k = 50$ найближчих сусідів для кожного вузла.

### 2.2. Запобігання ефекту ланцюжка (Chaining Effect)
Головна вада простих алгоритмів кластеризації у відкритих просторах — ефект «снігової кулі», коли два різних диктори з'єднуються через проміжний зашумлений запис:
1. **Поріг за калібрацією:** Усі ребра графа з косинусною подібністю $\cos(u, v) < \theta$ беззастережно видаляються.
2. **Взаємні сусіди (Mutual kNN):** Ребро між вузлами $u$ та $v$ зберігається лише тоді, коли $u$ входить у топ-$k$ сусідів $v$, **і одночасно** $v$ входить у топ-$k$ сусідів $u$. Це гарантовано розриває однобічні мости між кластерами.

### 2.3. Алгоритм Лейдена (Leiden) та внутрішній AHC
- Граф розбивається на спільноти за допомогою алгоритму **Leiden** (покращений Louvain з гарантією зв'язності спільнот та оптимізацією модулярності).
- Якщо спільнота виявляється надмірно великою (понад 200–500 записів), всередині неї запускається прецизійна **Agglomerative Hierarchical Clustering (AHC)** з критерієм середнього зв'язку (Average Linkage).

## 3. Методологія калібрації порогу без розмітки

Оскільки в корпусі Telegram відсутня істинна розмітка, класичну DET-криву побудувати неможливо. Застосовується трикомпонентний підхід:

```
1. Split-half пари ─────► Розподіл ПОЗИТИВІВ (Same-Speaker)
                          (зсунутий оптимістично — захист від недорозділення)

2. Випадкові пари ──────► Розподіл НЕГАТИВІВ (Different-Speaker)
                          (чистота негативів ≈ 1 - 1/N_дикторів)

3. 200 розмічених пар ──► АБСОЛЮТНИЙ ЯКІР у зоні невизначеності навколо порогу
```

### Деталі компонентів:
1. **Split-half позитивні пари:** Кожен довгий запис розбивається на 4 частини. Пари формуються між першою та третьою чвертями (щоб уникнути короткочасного фонового шуму мікрофона). Оскільки запис належить одній людині, це дає абсолютно безкоштовний емпіричний розподіл позитивних подібностей.
2. **Випадкові пари негативів:** Випадкова вибірка 100 000 пар з різних частин корпусу. При великій кількості людей імовірність випадкового потрапляння на одного мовця не перевищує часток відсотка.
3. **Експертний якір (200 пар):** Спеціаліст вручну прослуховує не випадкові пари, а виключно пари з косинусною подібністю у «сірій зоні» ($0,55 \le \cos \le 0,72$). Цей набір фіксується як золотий стандарт і **ніколи не бере участі в навчанні**.

## 4. Безрозміточні перевірки валідності кластеризації

| Перевірка | Методика вимірювання | Що ловить / Сигнал тривоги |
| :--- | :--- | :--- |
| **Split-Half Consistency** | Який відсоток половин одного й того самого повідомлення потрапив у спільний кластер? | **Поріг завищено / збій препроцесингу:** якщо показник падає нижче 95%, кластеризатор штучно дробить одного мовця на різні групи. |
| **Згода двох енкодерів** | Порівняння результатів SimAM-ResNet34 та ERes2NetV2 на спірних ребрах графа. | **Ненадійне злиття:** якщо перший енкодер бачить схожість 0.75, а другий 0.35 — ребро формується канальним шумом або музикою. Ребро відкидається. |
| **Детекція гігантського кластера** | Чи перевищує найбільший кластер **>1% від усього корпусу**? | **Chaining Effect / Музичний фон:** голосові повідомлення з популярною музикою або тишею об'єдналися в один гігантський хибний масив. |

## 5. Цикл ітеративного навчання на псевдомітках (Pseudo-Label Training)

Це стратегічний важіль, який дозволяє повністю ліквідувати розрив доменів (Domain Mismatch) без ручної праці розмітників.

```
                  ┌──────────────────────────────────────────────┐
                  ▼                                              │
         [Поточний енкодер]                                      │
                  │                                              │
                  ▼                                              │
       [Екстракція ембедингів]                                   │
                  │                                              │
                  ▼                                              │
    [Масштабна кластеризація (HNSW)]                             │
                  │                                              │
                  ▼                                              │
     [Фільтрація та генерація псевдоміток]                       │ ⟳ Ітерація 1, 2, 3
     (відкидання невпевнених кластерів)                          │ (2–4 доби на 4×4090)
                  │                                              │
                  ▼                                              │
  [AAM-Softmax Fine-Tuning на 4×RTX 4090]                        │
  (багатостадійний розклад, Large Margin)                        │
                  │                                              │
                  └──────────────────────────────────────────────┘
```

### 5.1. Наукове підґрунтя
У статті з дослідження SSL-кластеризації (DINO / MoCo на базі VoxCeleb2 без використання авторських міток):
- Початкова кластеризація DINO без міток дає EER ~2,62%.
- Ітерація 1: k-means (50k) → AHC → генерація міток → навчання AAM-ResNet = EER ~1,35%.
- Ітерація 2: оновлення ембедингів → перекластеризація → AAM fine-tuning = EER ~1,05%.
- Ітерація 3 з Large-Margin Fine-Tuning = **EER ~0,99%**.
- **Результат:** Модель, натренована **повністю без людської розмітки**, випередила supervised x-vector (1,59%) та практично зрівнялася з supervised ECAPA-TDNN (0,87%).

### 5.2. Адаптація під умови VoiceID
Завдяки наявності 4 × NVIDIA RTX 4090 проєкт VoiceID здатний запустити цей цикл безпосередньо на Telegram-даних:
1. Енкодер навчається ігнорувати артефакти стиснення Opus та мобільні мікрофони.
2. Критерій зупинки циклу: метрика на 200 якірних парах перестає зростати, а показник Split-Half Consistency виходить на плато.
